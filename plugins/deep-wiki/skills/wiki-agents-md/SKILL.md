# AGENTS.md Generator

Write `AGENTS.md` files that give coding agents the project context a README leaves out: exact commands, where things live, conventions, and what not to touch. Each one gets a companion `CLAUDE.md` that imports it.

Load `deep-wiki:wiki-conventions` if it is not already loaded. Its overwrite rules, generated-file marker, and read-only source rule apply here.

## When a File May Be Written

Check each target path separately before writing.

| The file | Do |
|----------|----|
| Does not exist | Write it |
| Exists and carries `<!-- generated by deep-wiki -->` | Replace it only when the calling workflow is in `regenerate` write mode; otherwise skip |
| Exists without the marker | Skip. Replace it only when the user explicitly chose to replace it in this run |

Report every file written, replaced, and skipped.

## Target Folders

By default: the repository root, `wiki/` (when it holds a deep-wiki site), and each monorepo package root (`packages/*`, `apps/*`, `services/*`, or a folder with its own build manifest that is built on its own). If the caller names folders, use only those.

Do not write one for `src/`, `tests/`, `lib/`, or `.github/` unless asked: agents read the nearest `AGENTS.md` up the tree, so a nested file is only worth having when the folder's commands or rules differ from its parent's. A nested file holds only what differs.

## Procedure (per target folder)

1. **Apply the table above.** If the file is skipped, go to step 6.
2. **Read the configuration**, never run it: manifests and their scripts (`package.json`, `pyproject.toml`, `Cargo.toml`, `*.csproj`, `go.mod`, `pom.xml`, `Makefile`, `Justfile`), CI workflows (the commands CI runs are the commands that work), container and linter configs.
3. **Read 3–5 representative source files** for naming, imports, error handling, and module layout.
4. **Write the file** from the template below, keeping only sections the folder has evidence for. No testing section without tests; no git section without CI or contribution docs.
5. **Verify by reading:** every command is a real script, target, or tool invocation found in step 2; every path exists; nothing is a placeholder. Do not execute project commands to check them.
6. **Companion `CLAUDE.md`:** if the folder now has an `AGENTS.md` (written now or already there) and no `CLAUDE.md`, write the one below. If a `CLAUDE.md` exists, apply the table above; when it is kept and does not mention `AGENTS.md`, recommend in the report that the user add an `@AGENTS.md` line.

## Template: Code Folder

```markdown
# <Project or Folder Name>: Agent Instructions
<!-- generated by deep-wiki -->

<One or two sentences: what this code is and its main technologies.>

## Commands

| Task | Command |
|------|---------|
| Install | `<from the manifest>` |
| Build | `<from the manifest or CI>` |
| Test (all / one file / one test) | `<from the manifest or CI>` |
| Lint / format | `<from the manifest or CI>` |

## Project Structure

| Path | Holds |
|------|-------|
| `<dir>/` | <what and why> |

## Conventions

- <Naming, imports, error handling, as observed in the source. One real example beats a paragraph.>

## Testing

- <Framework, where tests live, how fixtures work, what CI requires.>

## Git Workflow

- <Branching, commit message format, PR checks, taken from contribution docs and CI.>

## Boundaries

- **Always:** <checks to run before finishing>
- **Ask first:** <schema, public API, dependency, or CI changes>
- **Never:** <secrets, generated files, vendored code, production config>

## Documentation

- Wiki: `wiki/` (start at `wiki/index.md`; onboarding in `wiki/onboarding/`)
- LLM summary: `llms.txt` (full text: `wiki/llms-full.txt`)
```

Include the Documentation section only for files that exist. Keep the whole file under about 150 lines.

## Template: `wiki/AGENTS.md`

```markdown
# Wiki: Agent Instructions
<!-- generated by deep-wiki -->

Generated documentation for <project>, built as a VitePress site. Run commands from the repository root. Needs Node 22.12 or newer.

## Commands

| Task | Command |
|------|---------|
| Install | `npm --prefix wiki install` |
| Check every page | `npm --prefix wiki run check` |
| Regenerate section and onboarding index pages | `npm --prefix wiki run indexes` |
| Regenerate the llms files | `npm --prefix wiki run llms` |
| Preview | `npm --prefix wiki run dev` |
| Build (runs the site checks first) | `npm --prefix wiki run build` |

## Structure

| Path | Holds |
|------|-------|
| `catalogue.json` | Table of contents: sections, pages, order. The sidebar and index pages come from it. |
| `NN-section/*.md` | Pages. `NN-section/index.md` is generated. |
| `onboarding/` | Audience guides. `index.md` is generated. |
| `scripts/` | Checker and generators. Do not edit; they are replaced on regeneration. |
| `.deep-wiki.json` | Recorded settings (depth, repository URL, branch, base). |
| `.vitepress/` | Site config and theme. |
| `llms.txt`, `llms-full.txt`, `public/` | Generated by `npm --prefix wiki run llms`. |

## Adding or Changing a Page

1. Add the page to `catalogue.json` (a page outside the catalogue is reported, and removed by the next full regeneration).
2. Write `NN-section/page.md`.
3. Run `npm --prefix wiki run indexes`, then `npm --prefix wiki run check`, and fix every error.

Never hand-edit a generated `index.md`, the llms files, or `scripts/`.

## Rules the Check and Build Enforce

- Frontmatter `title` and `description` in double quotes; `title` is a name of at most 60 characters.
- `{{ }}` and tag-shaped text such as `List<T>` only inside backticks or code fences.
- Mermaid: `<br>` not `<br/>`, `autonumber` in every `sequenceDiagram`, dark palette, each diagram followed by `<!-- Sources: ... -->`.
- Tables have at most 5 columns.
- Links between pages are relative `.md` links that resolve; a broken one fails the build.
- Every claim cites a source file and line that exist.
```

## `CLAUDE.md`

Always exactly:

```markdown
# CLAUDE.md
<!-- generated by deep-wiki -->

@AGENTS.md
```

Claude Code expands the `@AGENTS.md` import, so the instructions load automatically.

## Quality Bar

| Do | Do not |
|----|--------|
| Give the exact command with its flags | Write "run the tests" |
| Describe this repository's conventions with one real example | Paste generic style advice or framework tutorials |
| State boundaries as Always / Ask first / Never | Bury warnings in prose |
| Leave out a section with no evidence | Invent a section, an owner, or a command |
| Keep nested files to what differs from the parent | Repeat the root file in every folder |

# Wiki Deploy (GitHub Pages)

Add `.github/workflows/deploy-wiki.yml` to build `wiki/` with VitePress and publish it to GitHub Pages.

**First load `deep-wiki:wiki-conventions`.** It defines `REPO_URL`, `HOST`, and `BRANCH`.

## Step 1: Preconditions

| Check | If it fails |
|-------|-------------|
| `wiki/package.json` exists | Stop: run `/deep-wiki:build` first. |
| `HOST` is `github` | Stop: GitHub Pages needs a GitHub remote. For Azure DevOps, point the user to `/deep-wiki:ado`. |
| `.github/workflows/deploy-wiki.yml` does not exist | Stop and report that it already exists. Don't change it unless the user asked. |
| No other Pages workflow (`grep -rlE "deploy-pages\|upload-pages-artifact" .github/workflows/`) | Ask (main session) whether to add `deploy-wiki.yml` alongside it. A subagent or crisp run skips and reports instead. |

## Step 2: Base Path

Get the owner and repo name: `gh repo view --json owner,name --jq '.owner.login + "/" + .name'`. Without `gh`, parse `REPO_URL`, which is already normalized to `https://github.com/<owner>/<repo>`.

| Repo name | Pages URL | `BASE` in `wiki/.vitepress/config.mts` |
|-----------|-----------|----------------------------------------|
| `<owner>.github.io` | `https://<owner>.github.io/` | `'/'` |
| anything else | `https://<owner>.github.io/<repo>/` | `'/<repo>/'` |
| custom domain (a `wiki/public/CNAME` file exists) | `https://<domain>/` | `'/'` |

Update the `BASE` constant (or `base:` key) in `config.mts` if it differs.

If you changed `BASE`, the site routes in both deployment copies, `wiki/public/llms.txt` and `wiki/public/llms-full.txt`, now point at the old base. Rewrite each one for the new base, following the deployment-copy rules in the `deep-wiki:wiki-llms-txt` skill. Apply its overwrite guard to each file separately: rewrite a file only if it contains `<!-- generated by deep-wiki -->`. If a file has no marker, leave it alone and tell the user its links still use the old base. List the refreshed files in the Step 5 report.

## Step 3: Lockfile

| Situation | Install step | `setup-node` cache lines |
|-----------|--------------|--------------------------|
| `wiki/package-lock.json` exists or can be created now (`cd wiki && npm install`) | `npm ci` | keep `cache: npm` and `cache-dependency-path` |
| No lockfile and installing is not allowed (crisp mode) | `npm install` | **remove both lines**; `setup-node` fails when the cache path is missing |

## Step 4: Write the Workflow

Replace `BRANCH` with the resolved default branch. These action versions were current in November 2026. Before writing, check them with `gh api repos/actions/<name>/releases/latest --jq .tag_name` and use the latest major.

```yaml
name: Deploy Wiki to GitHub Pages

on:
  push:
    branches: [BRANCH]
    paths:
      - 'wiki/**'
      - '.github/workflows/deploy-wiki.yml'
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0 # full history for VitePress lastUpdated

      - uses: actions/setup-node@v7
        with:
          node-version: 24
          cache: npm
          cache-dependency-path: wiki/package-lock.json

      - uses: actions/configure-pages@v6

      - name: Install dependencies
        run: npm ci
        working-directory: wiki

      - name: Build
        run: npm run build
        working-directory: wiki

      - uses: actions/upload-pages-artifact@v5
        with:
          path: wiki/.vitepress/dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v5
```

## Step 5: Report

Tell the user:

1. Which files were created or changed (workflow, `config.mts` base, `wiki/public/llms.txt` and `llms-full.txt`, lockfile).
2. To commit them: `git add .github/workflows/deploy-wiki.yml wiki/` and push to `BRANCH`.
3. **Required one-time setup:** in the repository, go to **Settings → Pages → Build and deployment → Source** and choose **GitHub Actions**. Without this, the workflow runs but nothing is published. With `gh` and admin rights: `gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow`. Only run that if the user asks; it changes repository settings.
4. The site URL from Step 2.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| Site loads without CSS or 404s on assets | `BASE` doesn't match the repo name (Step 2) |
| `npm ci` fails: missing lockfile | Commit `wiki/package-lock.json`, or switch to the no-lockfile variant (Step 3) |
| setup-node: "Some specified paths were not resolved" | Cache lines left in while no lockfile exists (Step 3) |
| Workflow never runs | The push didn't touch `wiki/**`, or it went to a branch other than `BRANCH` |
| `deploy` job: "Pages not enabled" / 404 from deploy-pages | Do the Settings → Pages step |
| Mermaid diagrams missing | `mermaid` and `vitepress-plugin-mermaid` missing from `wiki/package.json` |
| `npm ci` / `npm install`: `ERESOLVE` on peer `mermaid@"10 \|\| 11"` | The `overrides` entry for `vitepress-plugin-mermaid` is missing from `wiki/package.json`; restore it from the `wiki-vitepress` template |
| `EBADENGINE` or a Mermaid build error on old Node | Mermaid 12 needs Node 22.12+; keep `node-version` at 22.12 or newer |

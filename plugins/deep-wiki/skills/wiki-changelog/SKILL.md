# Wiki Changelog

Turn git history into a categorized, user-facing changelog.

Load `deep-wiki:wiki-conventions` if it is not already loaded. It defines repository resolution, commit-link formats, VitePress-safe Markdown, and the overwrite rules.

## Inputs

| Argument | Meaning | Default |
|----------|---------|---------|
| A revision range (`v1.2.0..HEAD`, `abc123..def456`) | Commits to include | none |
| `--since <date>` (`2026-10-01`, `"4 weeks ago"`) | Start date | 30 days ago |
| `--write` | Also write `wiki/changelog.md` | Print only |

## Procedure

1. Collect commits: `git log <range> --no-merges --date=short --pretty=format:'%H%x09%h%x09%ad%x09%s'` (use `--since` when no range is given). Read bodies (`%b`) only for commits that look breaking or are ambiguous.
2. Group by period: one group per day for the last 7 days, then one per ISO week. For a tag range, use one group per tag.
3. Classify each commit. Conventional-commit prefixes win over keywords:

   | Emoji | Category | Signals |
   |-------|----------|---------|
   | ⚠️ | Breaking Changes | `!:` in the prefix, `BREAKING CHANGE:` in the body, `breaking`, `migrate`, `deprecate` |
   | 🆕 | New Features | `feat`, `add`, `new`, `implement`, `introduce` |
   | 🐛 | Bug Fixes | `fix`, `bug`, `patch`, `resolve`, `hotfix` |
   | 🔄 | Refactoring | `refactor`, `restructure`, `reorganize`, `clean` |
   | 📝 | Documentation | `docs`, `readme`, `comment` |
   | 🔧 | Configuration and CI | `config`, `ci`, `build`, `chore` |
   | 📦 | Dependencies | `deps`, `upgrade`, `bump`, `lock` |

4. Merge related commits into one user-facing line in the README's vocabulary. Link each line to its commit(s): the short SHA as link text, the full SHA in the URL, in the conventions' commit-link format.
5. Put every identifier, file name, generic type, and template expression taken from a commit subject in backticks (`` `List<T>` ``, `` `${{ github.ref }}` ``). Outside backticks they break the site build.

## Output Format

```markdown
## 2026-11-20: Faster event handling

One- or two-sentence summary of the period.

### ⚠️ Breaking Changes

- Description, with migration notes. ([abc1234](REPO_URL/commit/<full sha>))

### 🆕 New Features

- Description. ([def5678](REPO_URL/commit/<full sha>))
```

Omit empty categories. Always list breaking changes first.

## Writing `wiki/changelog.md` (`--write` only)

1. If `wiki/changelog.md` exists without the `<!-- generated by deep-wiki -->` marker, do not touch it; print the changelog and say why it was not written.
2. Otherwise write the file, replacing a marked one, starting with:

   ```markdown
   ---
   title: "Changelog"
   description: "Changes to <project> from <start> to <end>."
   ---

   # Changelog
   <!-- generated by deep-wiki -->
   ```

   followed by the period groups. A rerun replaces the whole file with the range it was given; to keep older entries, widen the range.
3. Load `deep-wiki:wiki-vitepress` and run the bootstrap command from conventions section 10, then run `node wiki/scripts/check-wiki.mjs wiki --page changelog.md` and fix every error.
4. If `wiki/llms.txt` exists, run `node wiki/scripts/gen-llms.mjs wiki` so the changelog is included.
5. Tell the caller the page appears in the site's top navigation and under "More" in the sidebar after the next build.
